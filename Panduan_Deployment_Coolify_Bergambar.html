BAB 1: ARSITEKTUR JARINGAN & ATURAN EMAS WILDCARD

Kenapa Anda Bebas dari Mengubah Reverse Proxy Manual?

Di masa lalu, setiap kali membuat aplikasi web baru di VPS, developer harus melakukan SSH ke server utama dan mengedit file /etc/caddy/Caddyfile secara manual. Sekarang hal tersebut dilarang dan tidak diperlukan lagi karena jaringan Proxsis telah dipasangi konfigurasi Wildcard Reverse Proxy otomatis.

• DILARANG menggunakan domain kustom di luar *.connect.proxsis.com tanpa koordinasi DNS dengan tim IT Biztech.

BAB 2: SETUP TOKEN UNTUK DEPLOYMENT OTOMATIS (AI AGENT)

Cukup konfigurasi 1 kali, selanjutnya AI Agent dapat mendeploy website hanya dari chat prompt.

Langkah 1: Mengambil Personal Access Token (PAT) di GitHub

  1. Buka github.com dan login ke akun GitHub Anda.
  2. Klik foto profil Anda di pojok kanan atas → pilih Settings.
  3. Pada bilah menu sebelah kiri paling bawah, klik Developer settings.
  4. Pilih menu Personal access tokens → klik Tokens (classic).
  5. Klik tombol Generate new token → pilih Generate new token (classic).
  6. Isi form:
    • Note: Masukkan nama, misal Coolify Deploy Agent
    • Expiration: Pilih 90 hari atau No expiration
    • Scopes: Centang pilihan repo (Full control of private repositories)
  7. Klik tombol hijau Generate token di bagian paling bawah.
  8. Salin kode token yang muncul (berawalan ghp_...) dan simpan dengan aman.

Langkah 2: Mengambil API Token di Dashboard Coolify

  1. Buka dashboard Coolify melalui link resmi: https://connect.proxsis.com lalu login.
  2. Klik menu navigasi Keys & Tokens (atau klik avatar profil → API Tokens).
  3. Klik tombol Create New Token atau Add New Token.
  4. Beri nama token, misalnya: AI Deployment Token.
  5. Pilih role/permission: Root atau Admin.
  6. Klik tombol Create, lalu salin token yang muncul (berformat 3|... atau 9|...).

Langkah 3: Menempelkan Token ke File AI_DEPLOYMENT_CONFIG.md

Buka file AI_DEPLOYMENT_CONFIG.md di folder proyek Anda, lalu isi token pada baris berikut:

# 1. Masukkan GitHub Token Anda: GITHUB_TOKEN="ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" # 2. Masukkan Coolify API Token Anda: COOLIFY_TOKEN="9|xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" # 3. URL Repository GitHub (OPSIONAL - Boleh Dikosongkan): GIT_REPOSITORY=""
🔒 Keamanan Terjamin: File AI_DEPLOYMENT_CONFIG.md sudah dimasukkan ke dalam .gitignore, sehingga token rahasia Anda tidak akan pernah terunggah ke repositori GitHub publik.

BAB 3: CONTOH PERINTAH CHAT KE AI AGENT

Setelah token terpasang, cukup ketik satu kalimat perintah di chat untuk mendeploy.

“Tolong deploy website di folder ini ke Coolify.”

→ Aksi Otomatis AI: AI Agent akan membuat repositori baru di GitHub akun Anda secara otomatis, melakukan git commit dan git push, mendaftarkan project di Coolify, mengatur subdomain unik, menjalankan build, dan mengembalikan link web yang sudah aktif.

SKENARIO 2 Deploy dari Tautan Repository GitHub Langsung
“Deploy project ini ke Coolify: https://github.com/Proxsis-Biztech/Sitkorp_Status.git”

→ Aksi Otomatis AI: AI Agent langsung mengambil link repo tersebut, mendeteksi jenis aplikasi (Docker/Node/Static), mengarahkan target ke server Sitkrop Infra, dan mengeksekusi deployment.

SKENARIO 3 Deploy dengan Subdomain Tertentu Pilihan Anda
“Deploy website ini ke Coolify dengan domain https://synergi.connect.proxsis.com”

→ Aksi Otomatis AI: AI Agent akan langsung menyetel rute Traefik ke subdomain synergi.connect.proxsis.com, sehingga setelah build selesai website langsung bisa diakses publik dengan SSL aktif.

BAB 5: STRATEGI MANAJEMEN MULTI-PT & SHARING SERVER

Panduan arsitektur dan pembagian akses antar-PT (misal: PT Proxsis & Co dan PT Synergi) di Coolify.

1. Mengapa Satu Server Fisik Tidak Bisa Dibagi ke Beda Team Secara Native?

Di arsitektur Coolify v4, sebuah server fisik/IP (seperti 192.168.10.21) terikat eksklusif ke satu team_id. Jika ada Team baru dibuat di dashboard, Team tersebut tidak bisa menambahkan server yang sama karena Coolify memblokir duplikasi IP untuk mencegah tabrakan port Docker dan Traefik proxy.

2. Tabel Perbandingan 3 Solusi Pembagian Antar-PT

Pendekatan Kelebihan Kekurangan / Konsekuensi Rekomendasi Penggunaan
Opsi 1: Project per PT (1 Team Sama) • Hemat resource (1 server dipakai bersama)
• Mudah dipantau oleh tim IT Pusat
• 1 Project bisa menampung banyak aplikasi & DB		 • RBAC masih tingkat Team (user Admin bisa melihat project PT lain)
• Berbagi kuota CPU/RAM server		 Sangat Disarankan jika deployment dikelola terpusat oleh IT Pusat / Biztech.
Opsi 2: Auto-Deploy Git Webhook • Hemat server (1 server bersama)
• Developer PT sama sekali tidak bisa mengintip project lain karena tidak login Coolify		 • Developer tidak bisa melihat log real-time di UI Coolify (harus minta bantuan IT) Paling Aman & Praktis jika developer PT hanya butuh fitur auto-deploy saat git push.
Opsi 3: Virtualisasi (VM / LXC Terpisah) • Isolasi 100% aman (Team terpisah)
• CPU/RAM terbagi rata secara terisolasi
• Masing-masing PT punya server sendiri		 • Butuh sedikit RAM/CPU ekstra untuk OS VM baru di Proxmox/ESXi Sangat Disarankan jika masing-masing PT punya tim DevOps sendiri yang wajib login dashboard.

BAB 6: TROUBLESHOOTING & CHECKLIST VERIFIKASI

Solusi cepat untuk kendala umum yang sering ditemui saat deployment.

1. Kenapa Muncul Status 'Changes Pending'? Setiap kali mengubah nama domain atau port, Coolify tidak langsung mematikan aplikasi yang sedang berjalan. Klik tombol Redeploy di kanan atas untuk menerapkan konfigurasi domain baru ke Traefik proxy.
2. Bagaimana Mengisi Environment Variables (.env)? Buka menu Environment Variables di navigasi kiri aplikasi → klik Developer View → tempelkan (paste) seluruh isi file .env Anda → klik Save lalu klik Redeploy.
3. Aplikasi Berstatus Merah (Exited / Crash)? Buka tab Logs di menu aplikasi. Cari baris error berwarna merah di bagian paling bawah. Penyebab umum: port aplikasi berbeda dengan ports_exposes atau file .env database belum terisi.
4. Menghapus Aplikasi & Project Secara Bersih Coolify memiliki proteksi data: Project tidak dapat dihapus jika masih ada aplikasi aktif di dalamnya. Masuk ke aplikasi → buka Settings / Danger Zone → klik Delete, setelah bersih baru hapus Project-nya.
